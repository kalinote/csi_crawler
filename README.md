# CSI 采集器

基于 Scrapy 的多平台采集组件，通过 CSI 组件 SDK 接收任务配置，采集文章、博客和论坛帖子，并通过 RabbitMQ 输出结构化数据，也可导出为本地文件。

当前包含 **9 个平台适配：7 个文章类、2 个论坛类**。以下支持情况以当前源码实现为准，未经过目标网站的在线可用性验证；网站结构、接口和访问条件变化可能影响实际采集。

## 平台支持情况

配置 `inputs.platforms.value` 时，使用下表中的爬虫标识。

状态说明：✅ 已实现；❌ 未实现；🚫 不支持或禁用；⚠️ 部分实现，后接已实现的能力。

| 平台 | 爬虫标识 | 输出类型 | 栏目采集 | 关键词采集 | 评论或回复采集 |
| --- | --- | --- | --- | --- | --- |
| 暗网下 | `anwangxia` | 文章 | ✅ | ✅ | ❌ |
| Bearblog | `bearblog` | 文章 | ✅ | 🚫 | ❌ |
| 环球网 | `huanqiu_news` | 文章 | ✅ | 🚫 | ❌ |
| 凤凰网 | `ifeng_news` | 文章 | ✅ | ✅ | ❌ |
| 纽约时报中文网 | `nytimes_cn_news` | 文章 | ✅ | 🚫 | ❌ |
| 澎湃新闻 | `thepaper` | 文章 | ✅ | ✅ | ❌ |
| 世界论坛网新闻 | `wforum` | 文章 | ✅ | ✅ | ❌ |
| Javbus 论坛 | `javbus` | 论坛记录 | ✅ | ✅ | ✅ 主帖、回复、楼中楼 |
| 3DM 论坛 | `sdm_bbs` | 论坛记录 | ✅ | 🚫 | ⚠️ 主帖、回复、回复下的楼中楼 |

栏目采集使用 `crawler_type="default"`，关键词采集使用 `crawler_type="keyword"`。同一次任务中的平台共用这一模式；关键词任务应只选择关键词采集标记为 ✅ 的平台。

## 各平台栏目与能力

栏目名称需要与代码中的名称一致。未指定栏目时使用各平台的默认栏目；未知栏目会记录错误并跳过。

### 暗网下：`anwangxia`

- 支持栏目：`独家报道`，也是默认栏目。
- 支持栏目列表和关键词搜索结果分页，提取文章正文、标题、作者、发布时间、标签、封面和点赞数。
- 实现文件：[anwangxia.py](csi_crawlers/spiders/anwangxia.py)。

### Bearblog：`bearblog`

- 支持栏目：`发现`，也是默认栏目。
- 支持发现页分页，提取文章正文、标题、作者、时间和点赞数。
- 仅采集 `bearblog.dev` 及其子域名下的博客，不采集使用自定义域名的博客。
- 🚫 关键词采集：入口目前会直接抛出异常，其后的搜索代码尚未启用。
- 实现文件：[bearblog.py](csi_crawlers/spiders/bearblog.py)。

### 环球网：`huanqiu_news`

- 支持栏目：`国际`、`国内`、`军事`、`台海`、`评论`、`财经`、`科技`、`汽车`、`产业`、`文旅`、`健康`、`能源`、`房产`、`城市`、`长三角`。
- 默认栏目：`国内`。
- 通过频道配置和列表 API 获取文章，支持分页和详情解析。
- 下载正文图片及视频封面，并将链接替换为 Base64 数据；没有实现视频文件采集。
- 实现文件：[huanqiu_news.py](csi_crawlers/spiders/huanqiu_news.py)。

### 凤凰网：`ifeng_news`

- 支持栏目：`资讯`、`财经`、`科技`、`军事`、`体育`、`娱乐`、`汽车`、`房产`、`时尚`、`凤凰卫视`。
- 默认栏目：`资讯`。
- 支持栏目和关键词搜索，通过页面内嵌数据、列表 API 获取文章并分页。
- 提取文章正文、标题、作者、时间、标签及封面等字段。
- 实现文件：[ifeng_news.py](csi_crawlers/spiders/ifeng_news.py)。

### 纽约时报中文网：`nytimes_cn_news`

- 默认栏目：`中国`。
- 支持以下 41 个栏目名称，部分名称对应相同 URL：
  - `首页`、`国际`、`亚太`、`南亚`、`美国`、`美洲`、`欧洲`、`中东`、`非洲`。
  - `中国`、`时政`、`经济`、`社会`、`中外关系`、`港澳台`。
  - `商业与经济`、`全球经济`、`中国经济`、`交易录`、`镜头`。
  - `科技`、`科技公司`、`科技与你`、`科学`、`健康`、`教育`。
  - `文化`、`阅读`、`艺术`、`电影与电视`、`体育`。
  - `风尚`、`时尚`、`美食与美酒`、`生活方式`、`旅游`、`房地产`。
  - `观点与评论`、`专栏作者`、`观点`、`漫画`。
- 支持列表分页和文章解析；跳过双语页面，以及缺少标题或正文的文章。
- 实现文件：[nytimes_cn.py](csi_crawlers/spiders/nytimes_cn.py)。注意文件名与爬虫标识不同。

### 澎湃新闻：`thepaper`

- 支持栏目：`要闻`，也是默认栏目。
- 支持栏目列表和关键词搜索分页，列表使用 JSON API，详情读取页面中的 `__NEXT_DATA__`。
- 提取正文、标题、作者、时间、标签和封面等字段。
- 实现文件：[thepaper.py](csi_crawlers/spiders/thepaper.py)。

### 世界论坛网新闻：`wforum`

- 支持栏目：`即时新闻`、`热点新闻`、`中国军情`。
- 默认栏目：`即时新闻`。
- 支持栏目和关键词搜索分页，搜索参数使用 GBK 编码。
- 采集对象是新闻文章，输出 `entity_type="article"`，没有实现论坛帖子或评论采集。
- 实现文件：[wforum.py](csi_crawlers/spiders/wforum.py)。

### Javbus 论坛：`javbus`

- 支持栏目：`老司机福利讨论区`，也是默认栏目。
- 支持栏目和关键词搜索；搜索前获取表单令牌，再提交关键词。
- 采集主帖、回复和楼中楼，包含主题与父级关系、楼层、正文、分类、状态和互动数等字段。
- 输出记录的 `nsfw` 固定为 `true`。
- `page` 只限制列表或搜索结果页，帖内回复会继续翻页，不受该参数限制。
- 实现文件：[javbus.py](csi_crawlers/spiders/javbus.py)。

### 3DM 论坛：`sdm_bbs`

- 支持栏目：`PC新游发布与体验区`、`PC独立游戏资源区`、`PC游戏综合资源区`、`游戏杂谈区`、`游戏软硬件交流区`。
- 默认栏目：`游戏杂谈区`、`PC新游发布与体验区`。
- 采集主帖、回复和回复下的楼中楼，支持帖子状态、回复数及浏览数等字段。
- 跳过仅作者可见的楼层；当前没有采集主帖下的楼中楼。
- 🚫 关键词采集；`page` 同时限制列表页和每个帖子的回复页。
- 实现文件：[sdm_bbs.py](csi_crawlers/spiders/sdm_bbs.py)。

## 配置示例

以下配置选择澎湃新闻的要闻栏目，最多采集 2 个列表页，并导出为 JSONL 文件：

```json
{
  "meta": {
    "node_instance_id": "crawler_local",
    "action_id": "local_task"
  },
  "config": {
    "page": 2,
    "crawler_type": "default",
    "output": "articles.jsonl"
  },
  "inputs": {
    "platforms": {
      "type": "value",
      "value": ["thepaper"]
    },
    "resources_config": {
      "type": "value",
      "value": {
        "thepaper": {
          "sections": ["要闻"]
        }
      }
    }
  },
  "outputs": {}
}
```

保存为自己的任务配置后，在已安装 Scrapy 和 `csi_base_component_sdk` 的 `.venv` 环境中，从本目录通过 SDK 的 `csi-component run main:run --local-config 配置文件.json` 运行。组件入口为 `main:run`；直接执行 `python main.py` 不会启动采集。

关键词采集需将 `config.crawler_type` 改为 `"keyword"`，并在 `inputs` 中加入 `"keywords": {"type": "value", "value": ["科技", "人工智能"]}`。关键词模式不使用栏目选择。

[daily_task.json](daily_task.json) 提供了九个平台的栏目采集配置，设置 `page=10` 并输出到 RabbitMQ 队列。它只是配置样例，不包含定时调度逻辑。

## 通用能力与限制

| 配置或能力 | 当前支持情况 |
| --- | --- |
| 多平台采集 | ✅ 一个任务中可启动多个平台爬虫 |
| `page` | ✅ 列表页数限制；正数通常限制各栏目或关键词的列表页数，不是数据条数；未设置或不大于 0 时通常持续翻页至结束；论坛差异见上文 |
| `resources_config.<平台>.sections` | ✅ 为各平台指定栏目，名称必须与支持列表一致 |
| `resources_config.<平台>.proxy` | ✅ 已接入下载中间件，用于设置平台请求代理 |
| `resources_config.<平台>.headers` / `cookies` | ❌ 请求注入尚未接入，目前仅读取配置，不能依赖它们传递自定义请求头或登录状态 |
| `start_time` / `end_time` | ❌ 时间范围过滤尚未接入，目前仅解析参数 |
| `crawler_type` | ⚠️ `default` 和部分平台的 `keyword`；`user`、`video`、`forum` 模式尚未提供 |
| 用户采集 | ❌ 目前仅定义用户 Item，没有完整的用户采集功能 |
| RabbitMQ 输出 | ✅ 向多个 Reference 队列发送同一条记录；任一队列发布失败会使组件失败 |
| 文件输出 | ✅ `config.output` 支持 `.json`、`.jsonl`、`.csv`、`.xml`；未连接 Reference 输出且未显式指定队列时关闭 RabbitMQ 发布 |
| 清洗与分析 | ❌ 采集器主要输出原始 HTML；纯文本提取、安全 HTML、翻译和内容分析需要下游组件处理 |
| 跨任务增量采集 | ❌ 持久化采集检查点和跨任务去重尚未接入；记录 ID 不代表已跳过重复抓取 |

文章数据通常包含标题、正文、来源、作者和时间；论坛数据额外包含主题、父级、楼层和互动字段。字段能否获得取决于平台页面，并不保证每条数据都齐全。`nsfw`、`aigc` 等标记目前主要是站点代码固定赋值，不代表经过内容识别。

当前运行汇总采用“至少一个爬虫成功即正常返回”的规则。爬虫以 `finished` 关闭时会被记为成功，即使没有产出数据或发生过解析错误，因此应结合各平台产量和错误日志判断实际采集情况。

运行环境需要额外安装 CSI 组件 SDK；当前 [requirements.txt](requirements.txt) 仅列出 `dotenv`、`scrapy`，未固定版本。采集器目录目前没有覆盖各站点解析的自动化测试。
